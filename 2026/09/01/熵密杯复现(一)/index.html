前置：SM2 加密与签名

1. SM2 加密算法

本质：椭圆曲线版 ElGamal + KDF 密钥流异或 + SM3 完整性校验。

1.1 加密（持公钥 P=dGP = dGP=dG）

明文 MMM 先转为字节串（长度 klen 字节）：

  1. 产生随机数 k∈[1,n−1]k \in [1, n-1]k∈[1,n−1]；
  2. 计算 C1=kGC_1 = kGC1​=kG —— 曲线上的点，相当于"临时公钥"；
  3. 计算共享点 (x2,y2)=kP=kdG(x_2, y_2) = kP = kdG(x2​,y2​)=kP=kdG；
  4. KDF 派生密钥流（基于 SM3）：

    t=KDF⁡(x2 ∥ y2, klen)t = \operatorname{KDF}(x_2 \,\|\, y_2,\ \text{klen}) t=KDF(x2​∥y2​, klen)

klen：明文长度

  1. 异或加密：C2=M⊕tC_2 = M \oplus tC2​=M⊕t；
  2. 完整性校验值：C3=SM3⁡(x2 ∥ M ∥ y2)C_3 = \operatorname{SM3}(x_2 \,\|\, M \,\|\, y_2)C3​=SM3(x2​∥M∥y2​)；
  3. 输出密文 C=C1 ∥ C3 ∥ C2C = C_1 \,\|\, C_3 \,\|\, C_2C=C1​∥C3​∥C2​。

[!warning] 坑
标准密文顺序是 C1C3C2，但很多库（如 gmssl 老版本）默认 C1C2C3。对接/解题时先确认顺序，否则解密直接失败。

1.2 解密（持私钥 ddd）

  1. 从密文取出点 C1C_1C1​，并验证 C1C_1C1​ 是曲线上的合法点；
  2. 计算共享点：

    dC1=d(kG)=k(dG)=kP=(x2,y2)dC_1 = d(kG) = k(dG) = kP = (x_2, y_2) dC1​=d(kG)=k(dG)=kP=(x2​,y2​)

  3. 同样派生 t=KDF⁡(x2 ∥ y2, klen)t = \operatorname{KDF}(x_2 \,\|\, y_2,\ \text{klen})t=KDF(x2​∥y2​, klen)；
  4. 异或还原：M′=C2⊕tM' = C_2 \oplus tM′=C2​⊕t；
  5. 校验 SM3⁡(x2 ∥ M′ ∥ y2)=?C3\operatorname{SM3}(x_2 \,\|\, M' \,\|\, y_2) \stackrel{?}{=} C_3SM3(x2​∥M′∥y2​)=?C3​，相等才输出。

[!tip] 神奇之处
解密方不需要知道随机数 kkk——靠私钥 ddd 就能把加密时的共享点 (x2,y2)(x_2, y_2)(x2​,y2​) 还原出来。这就是椭圆曲线版 DH 密钥交换的思想。

2. SM2 签名算法

2.1 签名（持私钥 dAd_AdA​）

  1. 计算杂凑值（绑定了用户身份，这是与 ECDSA 的区别之一）：

    e=H(ZA ∥ M)e = H(Z_A \,\|\, M) e=H(ZA​∥M)

    其中 ZA=SM3⁡(ENTL ∥ IDA ∥ a ∥ b ∥ xG ∥ yG ∥ xA ∥ yA)Z_A = \operatorname{SM3}(\text{ENTL} \,\|\, \text{IDA} \,\|\, a \,\|\, b \,\|\, x_G \,\|\, y_G \,\|\, x_A \,\|\, y_A)ZA​=SM3(ENTL∥IDA∥a∥b∥xG​∥yG​∥xA​∥yA​)；
  2. 随机选 k∈[1,n−1]k \in [1, n-1]k∈[1,n−1]，计算 (x1,y1)=kG(x_1, y_1) = kG(x1​,y1​)=kG；
  3. 计算 r=(e+x1) mod nr = (e + x_1) \bmod nr=(e+x1​)modn；若 r=0r = 0r=0 或 r+k=nr + k = nr+k=n，重新选 kkk；
  4. 计算：

    s=(1+dA)−1⋅(k−r dA) mod ns = (1 + d_A)^{-1} \cdot (k - r\, d_A) \bmod n s=(1+dA​)−1⋅(k−rdA​)modn

输出签名 (r,s)(r, s)(r,s)。

2.2 验签（持公钥 PAP_APA​）

  1. 重算 e′=H(ZA ∥ M′)e' = H(Z_A \,\|\, M')e′=H(ZA​∥M′)；
  2. 计算 t=(r′+s′) mod nt = (r' + s') \bmod nt=(r′+s′)modn（t=0t=0t=0 则验签失败）；
  3. 计算点：

    (x1′,y1′)=s′G+tPA(x_1', y_1') = s'G + tP_A (x1′​,y1′​)=s′G+tPA​

  4. 计算 R=(e′+x1′) mod nR = (e' + x_1') \bmod nR=(e′+x1′​)modn，检查 R=?r′R \stackrel{?}{=} r'R=?r′。

2.3 数学推导

展开第 3 步的点运算：

sG+tPA=sG+(r+s) dAG=(s+(r+s)dA) GsG + tP_A = sG + (r+s)\,d_A G = \big(s + (r+s)d_A\big)\,G sG+tPA​=sG+(r+s)dA​G=(s+(r+s)dA​)G

由签名式 s(1+dA)=k−r dAs(1+d_A) = k - r\,d_As(1+dA​)=k−rdA​，移项：

s+s dA+r dA=k⟹s+(r+s)dA=ks + s\,d_A + r\,d_A = k \quad\Longrightarrow\quad s + (r+s)d_A = k s+sdA​+rdA​=k⟹s+(r+s)dA​=k

代回：

sG+tPA=kG=(x1,y1)sG + tP_A = kG = (x_1, y_1) sG+tPA​=kG=(x1​,y1​)

所以 x1′x_1'x1′​ 就是签名时的 x1x_1x1​，于是 R=(e+x1) mod n=rR = (e + x_1) \bmod n = rR=(e+x1​)modn=r。✅

[!note]
(1+dA)−1(1+d_A)^{-1}(1+dA​)−1 的作用
这个看起来别扭的因子，目的就是让私钥 dAd_AdA​ 在验签时恰好能被公钥 PA=dAGP_A = d_A GPA​=dA​G “配平”，同时防止从 sss 直接线性解出 dAd_AdA​。

3. 加密 vs 签名对比

维度 SM2 加密 SM2 签名
用途 保密传输消息 身份认证 + 完整性
私钥角色 解密方持有 签名方持有
随机数 kkk 的作用 生成共享点 kPkPkP 生成 x1x_1x1​ 混入 rrr
核心等式 dC1=kPdC_1 = kPdC1​=kP sG+tPA=kGsG + tP_A = kGsG+tPA​=kG
校验手段 C3C_3C3​（SM3） 比较 R=rR = rR=r
kkk 复用后果 泄露 M⊕M′M \oplus M'M⊕M′ 私钥直接泄露 ❗

[!tip] 结构上的共同点

  • 都有随机数 kkk，都算 kGkGkG；
  • 安全性都靠"从 kGkGkG 推不出 kkk"；
  • 核心技巧都是让对方用自己的秘密（私钥）配平出同一个点。

4. 攻击面

常见出题点：

  1. kkk 复用？（加密 & 签名都先查这个）
  2. kkk 是弱随机数 / 可预测？（LCG、时间种子、低位泄露 → HNP 上格）
  3. 私钥太小或部分泄露？（穷举 / 格攻击）
  4. 曲线参数被换成弱曲线？（阶 nnn 有小因子 → Pohlig-Hellman 求 DLP）
  5. 密文格式 C1C3C2 vs C1C2C3？
